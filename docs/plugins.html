What a plugin can do

Plugins run inside Dolphy and use the same design system and hardware access layer as the app.

dashboard_customizeCreate complete screens

Compose multi-screen Material 3 Expressive tools with state and callbacks.

hubExtend Dolphy

Add overlays, FABs, replace screens and hook named actions.

usbIntegrate hardware

Work with Bluetooth, Wi-Fi, NFC, USB, IR and Android services.

terminalUse system access

Call Java APIs and use Shell, Root or Shizuku when available.

warning
Trusted-code model

Plugins are not sandboxed. Read the source and only install code you trust.

Manifest parsing rules

The file is UTF-8 text and may be at most 48 MiB. String fields must be top-level single- or double-quoted assignments. id is lowercased, invalid characters become underscores and the result is limited to 64 characters. Missing fields fall back to the filename, version 1.0 and icon extension.

.dolphypluginapplication/x-dolphy-pluginUTF-848 MiB max[a-z0-9_-], 64 chars
library_books
Library plugins and dependencies

Library plugins start before consumers. __dependencies__ declares required plugin ids, determines startup order and prevents a consumer from starting while a dependency is missing or disabled. Java classes and objects may be exported by name and imported by dependent plugins.

code
Public format and runtime

A file opened or shared as .dolphyplugin is always executed by the embedded Python runtime. The repository still contains an internal JavaScript compatibility runtime for previously stored .js plugins, but it is not the documented public .dolphyplugin authoring format.

__id__ = "hello_dolphy"
__name__ = "Hello Dolphy"
__version__ = "1.0.0"
__icon__ = "rounded:waving_hand"

class HelloDolphy(BasePlugin):
    def on_plugin_load(self):
        self.add_module(
            title="Hello Dolphy",
            description="My first plugin",
            icon="waving_hand",
            screen="main",
            section="PLUGINS"
        )

    def screen_main(self, ui, api, state):
        return ui.scaffold(
            title="Hello Dolphy",
            content=ui.column([
                ui.card([
                    ui.text("It works!", "headlineSmall"),
                    ui.button("Say hello", self.say_hello)
                ])
            ], padding=16, spacing=12)
        )

    def say_hello(self):
        self.toast("Hello from Python")

Storage and updates

Switch and slider values use the same per-plugin JSON store as get_setting/set_setting. The host persists a value before calling on_setting_changed({key, value}); sliders emit the event when interaction finishes.

Where setting keys come from

There is no predefined key catalog. The plugin author creates any string key and uses the same spelling when reading, writing or declaring a Settings item. Keys only collide inside the same plugin because every pluginId has a separate store. Prefer stable names such as capture_enabled or radio.power; changing a key creates a new setting.

set_setting("capture_enabled", True)get_setting("capture_enabled", False){"type":"switch", "key":"capture_enabled", ...}
keyAny non-empty string chosen by the plugin. There are currently no reserved host keys.
valueAny json.dumps-compatible value: None, bool, number, str, list or dict.
defaultget_setting returns the supplied default when the key has never been saved.
lifetimeValues survive restarts and enable/disable. Deleting the plugin removes its entire settings store.

Integrate with existing features

Plugins can participate in Dolphy instead of living on an isolated screen.

fact_check
Integration points, not arbitrary patching

Screen hooks work for every route hosted by Dolphy. Action and service hooks work only where the app explicitly dispatches a named integration point. A plugin does not automatically intercept every Kotlin function.

layers
hook_screen(route, screen, mode, priority)

Add an overlay, top or bottom panel, FAB, or replace a route. Wildcards such as ir_* are supported.

bolt
hook_action(action, priority)

Inspect or change data, mark an action handled, or cancel it.

settings_input_component
provide_service(service, priority)

Provide an alternative hardware or logic backend with automatic fallback.

Screen hooks in detail

Routes and patterns are case-insensitive. The asterisk matches any number of characters. If several plugins match, higher priority wins where only one contribution can be used.

overlayRenders a full-size transparent layer over the existing screen.
topPlaces plugin UI in a Material surface at the top of the screen.
bottomPlaces plugin UI above the bottom navigation area.
fabPlaces compact plugin UI at the bottom end with navigation-safe padding.
replaceThe highest-priority replacement visually covers the built-in screen. Its underlying Compose screen still exists, so this is UI replacement rather than bytecode patching.
Useful route patterns
ir_*other/ir_*nfc_*other/nfc_*lan_*other/lan_*ble_section/*plugin/**

Use the navigation event while developing to inspect the current route. Routes with arguments are reported as their navigation template, for example nfc_result/{id}.

Action hooks and services

Action hooks form a priority-ordered pipeline. Services form a priority-ordered provider list. Both use JSON-compatible payloads.

NoneContinue without changing the action.
{"payload": {...}}Replace the payload passed to lower-priority hooks and the built-in implementation.
{"handled": true}Mark the action handled by the plugin. Use result to return a value.
{"cancel": true}Stop the hook chain and cancel the built-in operation.
FalseCancel immediately. True marks the action handled.

Add a first-class BLE Spam mode

    if payload["modeId"] == "lab_beacon":
        self.start_loop(payload["delayMs"])

def on_ble_mode_delay_changed(self, payload):
    self.delay_ms = payload["delayMs"]

def on_ble_mode_stop(self, payload):
    self.stop_loop()

def on_plugin_unload(self):
    self.stop_loop()

Download and apply plugin assets

download_assets requests all files as one batch. Each destination is confined to this plugin’s private directory; maxBytes limits each response and sha256 can verify it. Unless the user disabled confirmation in Plugin settings → Security, Dolphy shows the plugin name, file count and declared total size before network transfer. apply_asset imports a saved file into a stock Bad USB editor, user IR remotes or QR Audio Spoofer custom HTML.

Example: intercept every IR Storm transmission

IR Storm calls the shared infrared.transmit action once for every signal. The action payload does not contain the source screen, so a plugin that targets only IR Storm must remember the latest navigation event.

ir_storm_hook.dolphyplugin
__id__ = "ir_storm_hook"
__name__ = "IR Storm Hook"
__version__ = "1.0.0"
__icon__ = "rounded:settings_input_antenna"

from java import jarray, jint

class IrStormHook(BasePlugin):
    def __init__(self):
        super().__init__()
        self.current_route = ""

    def on_plugin_load(self):
        self.hook_action("infrared.transmit", 100)

    def on_navigation(self, route):
        self.current_route = str(route)

    def hook_infrared_transmit(self, payload):
        if self.current_route not in ("ir_storm", "other/ir_storm"):
            return None

        frequency = int(payload["frequency"])
        pattern = [int(value) for value in payload["pattern"]]
        ok = self.send_to_external_ir(frequency, pattern)
        return {
            "handled": True,
            "result": ok
        }

    def send_to_external_ir(self, frequency, pattern):
        android = self.api.getAndroid()
        java_pattern = jarray(jint)(pattern)
        return android.irTransmit(frequency, java_pattern)

DEX loading and library plugins

Keep a plugin as one readable Python file while embedding compiled Java or Kotlin code and sharing native capabilities with other plugins.

verified_user
DEX is native trusted code

A loaded DEX runs inside the Dolphy process with the app permissions. Always publish the SHA-256, verify it before loading and never execute an untrusted downloaded payload.

Embed and load a raw DEX

Store the raw DEX as Base64 in the .dolphyplugin file. Dolphy removes whitespace, decodes it, verifies SHA-256 and creates the class loader. Raw DEX uses InMemoryDexClassLoader on Android 8+; older Android and ZIP-based JAR/APK payloads use a private read-only code-cache file and DexClassLoader.

native_radio_core.dolphyplugin
__id__ = "shared_radio_core"
__name__ = "Shared Radio Core"
__version__ = "1.0.0"
__library__ = True

DEX_SHA256 = "48c3cb64ad3c0e82b7352549f7568e4e42119fc6b066a050054474e6fffca28c"
DEX_BASE64 = "ZGV4CjAzNQ..."

class SharedRadioCore(BasePlugin):
    def on_plugin_load(self):
        loader = self.load_dex_base64("radio_core", DEX_BASE64, DEX_SHA256)
        bridge_class = loader.loadClass("dev.dolphy.radio.RadioBridge")
        constructor = bridge_class.getDeclaredConstructor()
        constructor.setAccessible(True)
        bridge = constructor.newInstance()
        self.export_java_class("radio.bridge.class", bridge_class)
        self.export_java_object("radio.bridge", bridge)

    def on_plugin_unload(self):
        bridge = self.import_java_object("radio.bridge")
        if bridge is not None:
            bridge.close()

Export classes and live objects

Exports are process-local named references. A library owns every class and object it exports; disabling, updating or deleting that library removes its modules and exports from the registry.

Expose Dolphy internals from open source

Java reflection helpers

These helpers search the app plus DEX modules of declared dependencies. They can inspect private members, read or write fields, call a matching method and construct an object. They do not install a method hook and do not intercept future calls.

reflection_library.dolphyplugin
__id__ = "dolphy_reflection_facade"
__name__ = "Dolphy Reflection Facade"
__library__ = True

class ReflectionFacade(BasePlugin):
    def on_plugin_load(self):
        activity_class = self.find_java_class("com.droid.dolphy.MainActivity")
        if activity_class is None:
            raise RuntimeError("MainActivity class is unavailable")
        description = self.inspect_java_class(activity_class)
        self.export_java_class("dolphy.main_activity", activity_class)
        self.set_setting("known_methods", [item["name"] for item in description["methods"]])
warning
Reflection compatibility

Private names and signatures may change between Dolphy builds. Catch exceptions, declare the library dependency, verify the app version yourself and prefer stable screen, surface, action and service hooks whenever one exists. Overload resolution does not perform arbitrary type conversion.

extension
Class access versus host hooks

Class export enables reflection, construction and method calls; it does not rewrite an already compiled Compose function. Use hook_screen for screens, hook_surface("bottom_bar") for the navigation panel, action hooks for logic and service providers for replaceable hardware backends. A DEX library can hide reflection behind a stable facade shared by other plugins.

Limits and lifecycle

A .dolphyplugin may be 48 MiB; each decoded DEX/JAR/APK payload may be 32 MiB. Disabling, deleting or updating a library automatically disables enabled dependent plugins first; re-enable consumers when the library is ready. Android cannot unload a Class once code has referenced it. Dolphy drops loaders and exports when the owner stops, but a process restart is the only guaranteed complete unload after an update. Keep export names globally unique and close threads, receivers, sockets and hardware handles in on_plugin_unload.

Lifecycle and state

Release scans, USB connections and background work when the plugin stops.

1on_plugin_load

Register modules, hooks and services.

2screen_*

Return UI for each plugin screen.

3on_event

Receive navigation, NFC and activity events.

4on_plugin_unload

Stop operations and release resources.

screen_<id>(ui, api, state)Primary renderer. main also accepts create_screen or screen_main. Missing screens render a native error placeholder.
callback(value)Python callables passed into UI builders receive only the value type produced by that component. Declaring fewer positional arguments is supported.
on_<event>(payload)Specific event handler wins; otherwise on_event(name, payload) is called.
hook_<action>(payload)Specific normalized action handler wins; otherwise on_action(action, payload) is called.
service_<id>_<operation>(payload)Specific normalized service handler wins; otherwise on_service(id, operation, payload) is called.
self.refresh()Invalidates registered plugin UI so screen functions run again with the latest plugin state.

Load and enable callbacks run when the session starts. Disable and unload callbacks run when it stops. Specific on_<event> handlers take precedence over on_event.

Install, update and recover

Dolphy is registered as a .dolphyplugin file handler and shows a safe preview before executing code.

  1. 1
    Open the file

    Tap a .dolphyplugin file in your file manager and choose Dolphy.

  2. 2
    Review metadata

    Check the icon, author, version and description on the installation page.

  3. 3
    Install

    Code starts only after you press Install. Reopening the file updates it.

previewReads metadata and size without executing Python; shows whether the same id is already installed.
install / updateSaves the source privately and starts it immediately unless Safe Mode is active. Installing the same id replaces the previous session and keeps its pinned state.
enable / disableStarts or stops the runtime and removes all registered modules, settings, screens, services and actions when disabled.
pin / sharePin changes ordering. Share exports the original source as application/x-dolphy-plugin with the .dolphyplugin extension.
deleteStops the runtime and permanently removes source, metadata, registrations and the plugin's private settings store.
startup failureA plugin that cannot start is saved disabled during installation; a corrupt stored source can be quarantined as .broken during restoration.
health_and_safety
Automatic Safe Mode

If the app closes while plugin code is running, the next launch disables every plugin and offers a crash log. You can then enable plugins one by one.

Safe Mode behavior

The recovery sheet explains that a plugin error closed the app and offers Copy log or Disable Safe Mode. Dismissing it leaves Safe Mode enabled and a persistent item remains on the Plugins screen. While active, every plugin is disabled and cannot be enabled until Safe Mode is turned off.
