# Dolphy 3.0 — نموذج التهديد (P0)

> هذه الوثيقة مرجعية أمنية حيّة. تُحدَّث مع كل مرحلة (P1–P4).

## 1. الأصول المحمية

| الأصل | مكان التخزين | حساسية |
|---|---|---|
| كلمات مرور Wi-Fi ومجموعات الاختبار | `SharedPreferences` مشفّرة (AES-256-GCM) | عالية |
| مفاتيح/بيانات NFC وIR | ذاكرة التطبيق والملفات | متوسطة |
| جلسات QR/WebSocket وسجلات الإدخال | ذاكرة مؤقتة + سجلات | متوسطة |
| صلاحيات Root/Shizuku | نظام التشغيل | حرجة |
| الإضافات (`*.dolphyplugin`) | ملفات التطبيق | حرجة |
| مفاتيح توقيع الإصدار | خارج المستودع (CI/Vault) | حرجة |
| رمز الودجت | `SharedPreferences` | متوسطة |

## 2. الفاعلون والثقة

| الفاعل | مستوى الثقة | القدرات |
|---|---|---|
| مالك الجهاز | موثوق | كل شيء بعد الموافقة |
| تطبيق آخر على الجهاز | غير موثوق | broadcasts، intents، محاولة قراءة الملفات |
| جهاز على نفس شبكة Wi-Fi | غير موثوق | طلبات HTTP/WS إلى المنفذ المحلي، صفحات QR |
| موقع ويب مفتوح في المتصفح | غير موثوق | CSRF، DNS rebinding، WebSocket hijacking |
| إضافة مثبّتة | غير موثوقة افتراضياً | صلاحيات التطبيق كاملة (حتى P3) |
| حزمة تعريف عتاد | غير موثوقة افتراضياً | تُشغّل كوداً (حتى P3) |
| مهاجم بجهاز مروّت | غير موثوق | وصول لنظام الملفات و`su` |

## 3. حدود الثقة

```
[UI / Compose] ──trusted──> [ViewModel / UseCase]
                                   │
                     ┌─────────────┼──────────────┐
                     ▼             ▼              ▼
             [Android APIs]  [Ktor local]   [Plugin runtime]
                     │             │              │
               trusted OS    untrusted LAN   untrusted code
```

- أي بيانات قادمة من الشبكة أو من إضافة أو من ملف مستخدم = **غير موثوقة**.
- لا تُمرَّر بيانات غير موثوقة إلى `Runtime.exec` أو `su` أو WebView دون تحقق.

## 4. نماذج التهديد الرئيسية (STRIDE)

| التهديد | المثال | الضابط في P0 | المتبقي |
|---|---|---|---|
| Spoofing | تطبيق يرسل Broadcast للودجت | رمز تثبيت عشوائي 256-bit داخل PendingIntent غير قابل للتعديل | نقل إلى `rootd`/AIDL في P1 |
| Tampering | تعديل قيمة مشفّرة في prefs | AES-GCM مع tag 128-bit | تدقيق سلامة الملفات في P1 |
| Repudiation | إنكار عملية حساسة | سجلات التطبيق (تُوسَّع في P3) | سجل تدقيق غير قابل للتعديل في P3 |
| Information disclosure | قراءة `wifi_passwords` أو إدخال QR | تشفير at-rest، إخفاء محتوى الإدخال من السجلات | منع لقطات الشاشة للشاشات الحساسة |
| Denial of service | إغراق `/ws` أو إطارات ضخمة | حد 64KB للإطار، مهلات، ربط LAN فقط | rate limiting في P2 |
| Elevation of privilege | تثبيت إضافة خبيثة | موافقة صريحة + تحذير | sandbox + توقيع في P3 |
| DNS rebinding | موقع يصل إلى `http://192.168.x.x:8080` | التحقق من `Host` و`Origin` | — |
| Cross-site WS | صفحة خبيثة تفتح `/ws` | رفض Origin غير المطابق | — |
| تسريب مفتاح التوقيع | مفتاح debug في الإصدار | فشل بناء release بدون keystore | إدارة مفاتيح في Vault |

## 5. افتراضات مهمة

1. الجهاز غير مروّت افتراضياً. ميزات Root تتطلب `su` صريحاً.
2. المستخدم هو مالك الجهاز ومسؤول عن قانونية الاستخدام.
3. الشبكة المحلية غير موثوقة: كل جهاز فيها قد يكون خبيثاً.
4. لا توجد خوادم سحابية لDolphy في P0.
5. التطبيق لا يخفي نشاطه ولا ينشئ persistence.

## 6. خارج النطاق (P0)

- عزل الإضافات (P3).
- `rootd` وallowlist العمليات (P1).
- توقيع حزم التعريف (P3).
- منع لقطات الشاشة/التسجيل (P4).
- اختبار اختراق خارجي (P4).

## 7. مراجعة دورية

- كل PR يمس الشبكة/التخزين/الصلاحيات يتطلب مراجعة بند أمني.
- تحديث النموذج عند إضافة نقل جديد (USB/BLE/SDR).
- مراجعة سنوية على الأقل أو عند حادث.
